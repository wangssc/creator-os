### 1.2 原始需求复述

用户提供的原始需求见 **附录 A（原文完整收录，未做任何删减）**。以下为按功能域归类后的复述，用于对齐理解，不替代附录 A。

系统由 **12 个功能模块 + 1 个全局框架** 构成，分为 4 个导航分组：

1. **首页**：大字标题「宇宙第一工作台」、副标题「你的想法，不必止于想法」、核心按钮「从一个想法开始」、侧边辅助区（发现与研究 / 文字 Aa 样式预览 / 自动化）。
2. **内容创作模块（6 个）**
   - 热点广场：聚合微博、知乎、抖音、今日头条、百度等 10+ 平台实时热点，卡片按平台分类，含标题、热度值、「去创作」「去拆解」按钮，顶部关键词搜索，全部免费无门槛。
   - 公众号创作：选题 → 大纲 → 写作 → AI 优化 → 排版 五阶段线性流程，顶部进度条，左操作右预览，支持一键跳转切换阶段。
   - 公众号一键成文：输入关键词或一句话需求，直接生成完整文章。
   - 小红书：选题生成、文案撰写、标签优化、配图建议。
   - 贴图号：双创建模式（表单创建 / 对话创建），表单含主题（必填）、行业、目标读者、内容类型、图片数量、人物模式、视觉风格，「生成卡片计划」一键出计划。
   - 爆款贴图复刻：核心逻辑「拆结构，不复制画面」；上传 1–8 张对标图（单张 ≤10MB）→ AI 拆解结构/信息层级/视觉钩子 → 用户选二创方向 → 生成原创图片规避版权；左流程右结果。
3. **分析模块（2 个）**
   - 账号诊断：接入平台数据，分析内容质量、粉丝增长、互动数据，输出优化建议。
   - 发布复盘：统计阅读/点赞/转发，分析表现，输出复盘报告。
4. **资源模块（2 个）**
   - AI超市：数据源 GitHub，按 Star 倒序，收录 1000+ AI 技能，分类（营销/编程/效率/设计/数据），全部中文翻译，支持关键词搜索；搜索栏 + 分类标签 + 卡片流。
   - AI书架：热门电子书聚合（如《程序员做饭指南》《人生进阶指南》《高性价比人生指南》《人人都能用英语》），分类（Agent/AI 编程/自动化/知识管理/生活技能/个人成长/英语学习），点封面跳原文；分类标签 + 封面卡片流 + 详情页（介绍、阅读提示、阅读原文按钮）。
5. **用户模块（1 个）**：积分查看 —— 当前积分、获取记录、兑换规则。

**模块总数确认：12 个（首页、热点广场、公众号创作、公众号一键成文、小红书、贴图号、爆款贴图复刻、账号诊断、发布复盘、AI超市、AI书架、积分查看）。本文档 12 个模块全量收录，无任何删减，路线图中各归其位。**

## 2. 产品定位：三种可能性的差异（含默认假设）

用户尚未最终确认项目目的。三种定位对功能深度、数据源、合规的要求差异极大，因此必须先区分。

| 维度 | A. 纯自己用 | B. 自己用 + 作品集（**默认假设**） | C. 做成对外产品 |
| --- | --- | --- | --- |
| 功能深度 | 够用即可，允许界面粗糙、流程断点 | 主流程必须能完整演示、无报错、视觉统一 | 全流程完整，边界情况全覆盖 |
| 数据源 | 手动录入、半自动、一次性的都行 | 可用预置样例数据，但必须标注「演示数据」 | 必须真实、可持续维护、可追溯来源 |
| 合规要求 | 低（自用不传播） | 中（公开演示不得出现侵权素材与真实他人数据） | 高（AI 生成内容标识、版权、抓取合法性、隐私、备案、内容审核） |
| 用户体系 | 不需要 | 不需要，单用户本地运行即可 | 必需（注册/登录/多租户/隔离） |
| 计费体系 | 不需要 | 积分可为本地模拟 | 必需真实计费与对账 |
| 部署与运维 | 本地跑 | 需可一键启动（含离线演示模式） | 需服务器、监控、灰度、SLA |
| 时间成本 | 1x | 约 1.5–2x | 约 3–5x |
| 必须补的能力 | 无 | 演示模式、样例数据集、3 分钟一键演示脚本 | 备案与域名【待定】、账号、支付、审核、客服 |

**默认假设（标记为假设，待用户确认）**：项目按 **B. 自己用 + 作品集** 定位推进。

理由：用户为 1 人独立开发、每周仅可投入约 6 小时、当前处于秋招面试高峰（11–12 月），C 定位的合规与运维开销会在半年内压垮单人产能；而 A 定位无法解释「12 个模块全量保留 + 极简视觉规范 + 完整导航体系」这种明显面向展示的设计投入。故 B 为最合理基线。

若用户后续改判为 C，需要追加：用户体系、内容审核流程、AI 生成内容标识、真实数据源合规评估、部署方案 —— 这部分工作量不计入本文档的 V1/V2/V3 估算，需重新排期。

## 4. 用户画像与核心场景

### 4.1 用户画像

**主用户（P1）：独立开发者本人**
- 26 岁左右，计算机/安全方向应届生，正在秋招面试高峰（11–12 月）。
- 编程基础偏弱，但在 AI 辅助下能独立交付工具；已独立完成 3 个 Python 项目（桌面加密工具、开源简历工具、LLM 安全评估工具）。
- 技术偏好：Python 熟练度最高，前端偏弱；对 React 生态只有零散经验。
- 时间：**每周约 6 小时**（折合约 0.75 人日/周），且时间碎片化（多为晚上与周末）。
- 内容侧：想做自媒体但没有稳定产能，卡在「找选题」和「写第一篇」。

**次用户（P2）：面试官 / 同行评审**
- 只会给你 3 分钟。看的是：视觉完成度、流程是否闭环、有没有真实可用的东西。
- 不看代码质量，看「这东西真的能用吗」。

**潜在用户（P3，V3 之后再考虑）**：中小自媒体运营者，1–3 人团队，需要多平台批量产出。

### 4.2 核心场景（4 个具体场景）

**场景 1｜周一早上 8:40，地铁上找选题（对应模块：热点广场 → 公众号创作）**
- 触发：这周必须发一篇，但完全没想法。
- 现状痛点：刷微博/知乎/抖音各 10 分钟，收藏一堆链接，回到电脑前还是不知道怎么下笔；信息在 4 个 App 之间无法对比热度。
- 期望路径：打开 Creator OS → 热点广场看 5 个平台的今日热点，按热度排序 → 点某个热点卡片上的「去创作」→ 直接带着这个选题进入公众号创作的第 1 阶段（选题），AI 给 5 个标题角度。
- 期望结果：8 分钟内锁定一个自己愿意写、且平台正在给流量的选题。
- 关键约束：手机上也要能用（响应式），因为决策发生在通勤路上。

**场景 2｜周五晚 21:00–22:30，一口气产出本周内容（对应模块：公众号创作 + 小红书 + 贴图号）**
- 触发：一周唯一一段完整可支配时间。
- 现状痛点：写公众号要 1.5 小时，写完就没力气再做小红书；小红书配图要另外找工具，风格不统一。
- 期望路径：五阶段走完公众号（大纲和初稿由 AI 出，自己只做删改和观点注入）→ 复制到公众号编辑器 → 同一选题切到小红书模块，自动生成 3 条不同角度的笔记文案 + 标签组合 → 切到贴图号，用「主题 + 行业 + 目标读者 + 视觉风格」表单生成 4 张卡片的计划，再批量出图。
- 期望结果：一周内容在 90 分钟内全部产出，且三个平台的内容是同源不同形（不是复制粘贴）。
- 关键约束：任何一个环节「重新生成」不能把我踢回上一步，不能丢我已写的内容。

**场景 3｜面试中的 3 分钟产品演示（对应模块：首页 + 全流程）**
- 触发：面试官问「你最近在做什么项目」。
- 现状痛点：之前的项目都是命令行工具，演示视觉冲击弱；讲不清「这个产品解决了谁的什么问题」。
- 期望路径：打开首页（大字标题 + 一句话定位）→ 点击「从一个想法开始」→ 输入一句话需求 → 3 分钟内走完「生成 → 改一句 → 预览 → 复制」的闭环 → 顺手切 AI超市和 AI书架展示资源沉淀能力。
- 期望结果：面试官记住「一个人做出了一个有 12 个模块的完整工作台」。
- 关键约束：**演示不能翻车**。必须有演示模式（预置样例数据、不依赖外网实时接口、失败可降级到本地缓存）。

**场景 4｜给父母做一份退休生活指南贴图（对应模块：贴图号 + 爆款贴图复刻）**
- 触发：用户原始需求中的示例「中老年人如何安排退休生活」，是真实想解决的问题。
- 现状痛点：会用 AI 写文案，但不会做图；做出来的图「不像小红书上那种」。
- 期望路径：贴图号表单：主题=中老年人如何安排退休生活，行业=健康养老，目标读者=40–50 岁用户，图片数量=4，人物模式=真实人物，视觉风格=温暖日常 → 生成卡片计划 → 逐张出图 → 导出。
- 如果已有对标爆款图：先在爆款复刻里上传 1–8 张，让 AI 拆出它的结构（封面钩子 / 信息层级 / 段落节奏），拿到「结构报告」后再回到贴图号按同样结构生成原创图。
- 期望结果：不懂设计的人也能做出「结构像爆款、画面是原创」的一组图。
- 关键约束：**只能拆结构，不能复制画面**，否则有版权风险（详见第 11 章）。

## 5. 功能架构总览：12 模块 + 实现依赖等级

### 5.1 依赖等级定义（L0–L4）

| 等级 | 名称 | 含义 | 稳定性 | 单人对策 |
| --- | --- | --- | --- | --- |
| L0 | 纯本地可实现 | 无外部服务依赖，纯前端逻辑 + 本地数据 | 极稳 | 直接做 |
| L1 | 依赖 LLM 文本 API | 依赖大模型文本能力（选题/大纲/写作/优化/翻译/报告） | 稳（可控降级） | 统一网关 + 重试 + 缓存 |
| L2 | 依赖多模态能力 | 依赖视觉理解（读图拆解）或文生图/图生图 | 中（模型能力与一致性有上限） | 降低期望、加人工干预点 |
| L3 | 依赖第三方开放数据 | 需平台开放接口/授权/账号绑定 | 中低（审核、权限、限流） | 手动导入作为主路径 |
| L4 | 依赖爬虫且需持续维护 | 无官方接口，只能抓取，随时会被反爬或改版打断 | 低（高脆弱） | 快照 + 手动刷新，不做强实时承诺 |

### 5.2 模块总表

| # | 模块 | 导航分组 | 核心能力 | 依赖等级 | 外部阻塞项 | 无阻塞时的降级实现 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 首页 | 首页 | 品牌呈现、全局入口、侧边辅助区 | **L0** | 无 | —— |
| 2 | 热点广场 | 内容创作 | 10+ 平台热点聚合、搜索、去创作/去拆解 | **L4（实时）／L0（快照）** | 各平台无公开热点接口，反爬策略频繁变更；抓取热度数据的合法性边界不清 | V1 用内置种子热点 JSON + 手动刷新，保留「实时更新」按钮位（不承诺时效） |
| 3 | 公众号创作 | 内容创作 | 选题→大纲→写作→AI 优化→排版 五阶段 | **L1** | LLM 额度与成本；长文一次生成易超上下文 | 分阶段分段生成，每阶段独立可重试 |
| 4 | 公众号一键成文 | 内容创作 | 一句话 → 完整文章 | **L1** | 同上；长文质量受模型能力限制 | 流式输出 + 一键转入五阶段继续改 |
| 5 | 小红书 | 内容创作 | 选题、文案、标签、配图建议 | **L1 + L2（配图建议的文字描述，不强制出图）** | 图文一体的出图依赖 L2；小红书平台接口未开放 | 配图先给「画面描述 + 尺寸 + 提示词」，出图交给贴图号模块 |
| 6 | 贴图号 | 内容创作 | 双创建模式（表单/对话）→ 卡片计划 → 出图 | **L1（计划）+ L2（出图）** | 文生图模型对「人物模式 + 风格一致性」的跨图一致性仍有明显缺陷 | V1 先只出「卡片计划」（文案 + 画面描述），出图列为 V2 |
| 7 | 爆款贴图复刻 | 内容创作 | 上传 1–8 图 → 结构拆解 → 二创 → 原创图 | **L2（视觉理解 + 图生图），最高难度项** | 视觉模型对「结构/信息层级/视觉钩子」的拆解稳定性不足；多图一致性；相似度自检缺可靠工具 | V3 才做；V1/V2 期间以「结构拆解报告」为最小可用形态（不出图也成立） |
| 8 | 账号诊断 | 分析 | 内容质量、粉丝增长、互动数据分析 + 建议 | **L3 → L4** | 微信公众号/小红书/抖音均无面向个人开发者的开放数据接口；绑定需企业资质或平台审核 | 手动导入（CSV/Excel/粘贴）为主路径 + LLM 规则化评分与建议，模块功能完整成立 |
| 9 | 发布复盘 | 分析 | 阅读/点赞/转发统计与复盘报告 | **L3（自动同步）／L0+L1（手动录入）** | 同账号诊断；自动同步需平台授权 | 手动录入 + 历史均值对比 + 报告生成，V1/V2 即可完整可用 |
| 10 | AI超市 | 资源 | GitHub 按 Star 倒序、1000+ 技能、分类、中文翻译、搜索 | **L0（GitHub 公开 API）＋ L1（批量翻译）** | GitHub API 限流（未授权 60 次/小时）；批量翻译成本 | 离线快照 JSON（脚本一次性生成 + 本地搜索），运行时不依赖外网 |
| 11 | AI书架 | 资源 | 电子书聚合、分类、封面卡片、详情页、跳原文 | **L0** | 电子书版权：**不得托管全文**；来源需可公开访问 | 纯静态配置 JSON + 元数据 + 外链跳转，不存正文 |
| 12 | 积分查看 | 用户 | 当前积分、获取记录、兑换规则 | **L0** | 真实计费需账户与支付体系（L3） | 本地记账（localStorage/SQLite），规则静态展示 |

**全局框架（不属于 12 模块，但为横切能力）**：左侧固定导航、路由无刷新切换、视觉 Token、统一生成类交互（重新生成/改参数不返回上级）、预览区实时编辑与保存、本地存储层、LLM 统一网关、演示模式、空态/加载/错误兜底。

> 关键结论：**12 个模块中，L0/L1 类有 7 个（首页、公众号创作、一键成文、小红书文案层、AI超市、AI书架、积分查看），可以立刻做；L2 类 2 个（贴图号出图、爆款复刻）拆成"文案/计划层（先做）+ 出图层（后做）"两段；L3/L4 类 3 个（热点广场、账号诊断、发布复盘）全部有手动/快照降级路径，因此不需要砍，只需要排到后面。**

## 8. 分期路线图 V1 / V2 / V3

**总原则**：
1. **12 个模块全部保留，任何一期都不删除模块。**
2. 分期只调整「实现深度」：L0/L1 走完整实现，L2 先做文案/计划层再做出图层，L3/L4 先做手动/快照降级版再升级为自动版。
3. 每期结束都是**可独立运行、可演示、可发布**的完整版本。

## 10. 交互与体验规范（横切，开发时须统一遵守）

| 编号 | 规范 | 理由 |
| --- | --- | --- |
| IX-1 | 左侧导航一键切换，无整页刷新，无过场动画（最多 150ms 淡入） | 用户明确要求「导航一键切换无刷新」 |
| IX-2 | 所有生成类页面统一使用同一套「生成控制条」：`[重新生成] [修改参数] [停止]`，位置固定在操作区底部 | 降低学习成本；14 处生成点行为一致 |
| IX-3 | 「重新生成 / 修改参数」**不返回上级、不清空输入、不丢已生成的上游内容** | 用户明确要求 |
| IX-4 | 多阶段流程（五阶段、复刻四步）允许点击任意已完成阶段回跳，回跳不删后续结果 | 用户明确要求「支持一键跳转切换」 |
| IX-5 | 预览区全部可编辑，编辑即自动保存（防抖 800ms），状态条显示「已保存 / 保存中」 | 用户明确要求「实时编辑与保存」 |
| IX-6 | 生成中显示骨架屏 + 流式文字；超过 8 秒给「仍在生成，可继续等待或停止」提示 | 避免误以为卡死 |
| IX-7 | 失败必降级：抓取失败回落本地快照、模型失败给重试与切模型、图片失败给占位图 + 重试 | L3/L4 模块的生存前提 |
| IX-8 | 破坏性操作（删除草稿、重开一篇）二次确认；非破坏性操作（重新生成、换阶段）不弹确认 | 减少打断 |
| IX-9 | 视觉只用浅绿 + 白 + 中性灰三系；平台色仅用于热点广场卡片底色 | 极简风格约束 |
| IX-10 | 空态必须有「下一步该做什么」的单一 CTA，不出现纯文字空页 | 低学习成本 |

## 11. 数据与合规风险

### 11.1 生成内容的合规责任

| 风险 | 表现 | 应对（写进需求） |
| --- | --- | --- |
| 事实性错误（幻觉） | 文章里的数据、人名、政策条款是编的，直接发出去会出事 | ① 所有生成内容标注「AI 生成，请核对事实」；② 数字/日期/政策类句子高亮提示待核（R-W12）；③ 不提供「一键发布到平台」能力，只提供「复制」，保留人工确认环节 |
| AI 生成内容标识义务 | 国内外平台与监管均要求对 AI 生成内容做标识 | ① 导出的图片/文本在元数据与服务条款中保留 AI 生成说明；② 界面固定提示语；③ 若转 C 定位，需按当时生效的法规补齐显式水印 |
| 违规内容（医疗、金融、养老夸大宣传等） | 贴图号示例涉及「中老年人退休/健康养老」，属于敏感垂类 | ① 内置敏感词与高危主张（疗效、收益承诺）提示；② 行业下拉中标注「需人工复核」的高危行业；③ 不生成医疗诊断、投资建议类内容 |
| 平台搬运判定 | 内容与爆款高度相似被判搬运、限流 | 复刻模块只产出结构，画面元素全新；加相似度提示（R-C07） |

### 11.2 第三方数据抓取的合法性边界

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 无授权抓取 | 微博/知乎/抖音/头条/百度均无面向个人开发者的热点开放接口，抓取属灰区 | ① 只抓「公开可见的榜单标题 + 公开热度值」，不抓用户内容、评论、私信等个人信息；② 严格限频（建议 ≥10 分钟一次、单次请求数最小化）；③ 遵守 robots.txt 与用户协议，遇明确禁止即停 |
| 数据二次分发 | 把抓来的榜单数据对外提供服务，可能涉不正当竞争/数据权益争议 | ① 每条热点强制标注来源平台与抓取时间；② 卡片外链回原平台详情；③ **不缓存全文、不做二次内容加工分发**；④ B 定位（自用+作品集）下风险可控，转 C 必须先做法律评估 |
| 反爬与稳定性 | 平台改版会导致模块整体不可用 | 降级到本地快照；「更新数据」失败时明确提示「已使用 X 小时前的数据」，不静默失败 |
| 账号数据（诊断/复盘） | 涉及用户自己账号的运营数据 | ① 默认手动导入，数据只存本地 SQLite；② 不采集他人数据；③ 上传第三方凭证（Cookie/Token）一律不支持，避免账号安全与协议风险 |

**不可跨越的红线（写进开发约束）**：
1. 不抓取需要登录才能看到的非公开内容。
2. 不存储、不传输用户上传的原图到第三方用于训练。
3. 不提供批量自动发布（自动化刷量/养号）能力。
4. 不做「绕过平台付费墙/权限」的任何实现。

### 11.3 电子书版权（AI书架）

| 原则 | 具体做法 |
| --- | --- |
| **不得托管全文** | 只存元数据：书名、作者/整理者、分类、封面缩略图、150–300 字介绍、阅读提示、来源链接。任何情况下不在本站点展示正文全文。 |
| 来源须可公开访问 | 只收录作者本人公开发布或明确允许传播的读物（如开源手册、作者公开分享的 PDF / 网页）。来源不明的一律不收。 |
| 封面版权 | 优先使用来源页提供的封面；无授权封面则用统一生成的占位封面（书名排版图），避免直接搬运出版社封面。 |
| 跳转而非镜像 | 「阅读原文」一律 `target=_blank` 跳转原始来源，并明示来源站点；不做 iframe 内嵌（易被判镜像）。 |
| 下架机制 | 提供一键下架配置（JSON 里 `enabled: false`），收到权利方通知可即时移除。 |

### 11.4 其他风险

| 风险 | 应对 |
| --- | --- |
